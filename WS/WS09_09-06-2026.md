Novena sesión. Tomás ya había creado el proyecto **`dwellia-app`** en Google Cloud.
Dos decisiones de arranque (acordadas con él):

- **Front a desplegar:** el **web Vite actual** como PWA (lo que ya funciona end-to-end).
  Expo sigue siendo el front de producción del canon, pero no está construido — el Vite
  es una PWA válida y rápida de poner online. El stack de abajo es idéntico, no se tira nada.
- **Alcance:** **privado / lo más rápido** — desplegar tal cual (modo dev, usuario único
  `dev|user`, sin login real) solo para verlo online y mostrarlo. Login real + aviso diario
  + fotos = Fase 2.

## 1. Infra desplegada (proyecto `dwellia-app`, region `europe-west1`)

| Pieza | Servicio | Detalle |
|---|---|---|
| **PWA (front)** | Firebase Hosting | sirve `apps/web/dist`; rewrite `/api/**` y `/health` → Cloud Run; SPA fallback. URL: **dwellia-app.web.app** |
| **Backend** | Cloud Run `dwellia-api` | imagen `…/dwellia/api:latest`, min-instances 0, 512Mi, `--allow-unauthenticated` |
| **Base** | Cloud SQL Postgres 16 | instancia `dwellia-db` (db-f1-micro, ENTERPRISE), base `mindful`, usuario `mindful` |
| **Imagen** | Artifact Registry | repo `dwellia`, build vía Cloud Build |
| **APIs** | run · sqladmin · artifactregistry · cloudbuild | habilitadas |

- **Conexión Cloud Run ↔ Cloud SQL:** unix socket (`--add-cloudsql-instances`), sin VPC.
  `MINDFUL_DATABASE_URL=postgresql+psycopg://mindful:***@/mindful?host=/cloudsql/dwellia-app:europe-west1:dwellia-db`.
- **Env del backend:** `MINDFUL_AUTH_MODE=dev` (usuario único), `MINDFUL_ENV=production`.
- **Migración + seed:** Cloud Run Job `dwellia-migrate` (misma imagen, `alembic upgrade head && python -m mindful_api.seed`). Cargó **6 categorías · 5 acciones · 69 cartas**.

## 2. Artefactos de deploy creados en el repo

- **`Dockerfile`** (raíz): backend FastAPI; contexto = raíz para incluir
  `M0_Motor_de_Contenido/data` (el seed lee desde la raíz). Preserva el layout `/app/apps/api`.
- **`.dockerignore`**: solo `apps/api` + `M0/data` van a la imagen.
- **`firebase.json`** + **`.firebaserc`**: hosting con rewrites a Cloud Run.
- **`apps/web/public/`**: `manifest.webmanifest`, `icon-192/512.png`, `apple-touch-icon.png`,
  `icon.svg`, `og.png`. Meta tags PWA + Open Graph en `index.html`.

## 3. Identidad visual (decisión de Tomás: **mini-carta Dwellia**)

El ícono ES una cartita en miniatura, idéntica al objeto central de la app: papel crema
`#EFE6D3`, franja dorada `#E2A93B` (Gratitud) y el dibujo real del **amanecer** de M0.
- **Ícono de app** (192/512 + apple-touch 180): lo que aparece al "Agregar a inicio".
- **Imagen del link (Open Graph, 1200×630):** la misma carta + "Dwellia · One quiet pause
  a day" + "Una pausa al día. Por fuera del teléfono.". Es la tarjeta que se ve al pegar el
  link en WhatsApp/iMessage. Ambas comparten lenguaje visual (mismo dibujo de M0).
- **Salvedad del link (Fase 2):** como el front es SPA y los scrapers no corren JS, hoy es
  **una sola imagen de marca para todos los links**. Mostrar *la carta específica* compartida
  pide render server-side por token → diferido.

## 4. Verificación end-to-end (contra la URL pública, usuario descartable `smoke|test`)

`/` 200 · título OK · `/api/contenido/resumen` → **69 cartas** (rewrite a Cloud Run OK) ·
`/og.png` y `/manifest.webmanifest` 200. Funnel: perfil+términos → categorías → carta del
día (M2, entregó *Calma/Caminar*) → cierre ⭐4 + reflexión (M3) → baúl (M4) → borrado (204).
Entrada de prueba eliminada; **`dev|user` queda con el baúl vacío** para arrancar limpio.

## 5. Notas / deudas

- **Seguridad (consciente):** modo dev = cualquiera con la URL es el mismo `dev|user` y
  comparte el baúl. Aceptable para "privado, mostrarlo". Login real (Firebase) = Fase 2
  (ya escrito e inactivo en `auth.py`).
- **Credenciales:** `.deploy/secrets.env` (gitignored) — password de la base.
- **Endurecimiento sugerido:** mover `MINDFUL_DATABASE_URL` a Secret Manager (hoy env var).
- **Costo aprox.:** ~$10/mes (Cloud SQL chica; Cloud Run + Hosting ~gratis a este tráfico).
