## 1. Aviso diario por email

**Arquitectura (patrón WS07, simplificado a la escala real):** Cloud Scheduler
(cada 15 min) → `POST /api/internal/aviso-diario` (header `X-Aviso-Secret`) →
barrido en el request (sin Redis/worker: decenas de usuarios, no miles).

- **`services/email.py`**: 3 modos por env (`MINDFUL_EMAIL_MODE`): `off` (default,
  dev/tests) · `log` (stdout) · `smtp` (real; SendGrid = host `smtp.sendgrid.net`,
  user literal `apikey`, pass = API key). Nunca levanta: un email caído no tumba
  el barrido.
- **`services/aviso.py`**: manda si `aviso_activo` ∧ términos aceptados ∧ su hora
  local ≥ `hora_aviso` (zoneinfo por usuario) ∧ hoy no se le mandó ∧ hoy no guardó
  su pausa. Comparar `≥ hora` (no ventana exacta) = auto-reparable si un tick se
  pierde. **El email NO crea la entrega** (canon WS15: la carta se revela al abrir
  la app) — solo invita con CTA a `/hoy`. HTML simple con la paleta (crema/sage).
- **Columna nueva `usuarios.ultimo_aviso_fecha`** (Date, fecha LOCAL del último
  envío; migración `f6a7b8c9d0e1`) = dedup de 1 email/día. Si ya guardó la pausa
  se estampa sin mandar (no re-evaluar el resto del día).
- **`routers/interno.py`**: sin `MINDFUL_AVISO_SECRET` configurado → 404 (apagado);
  header incorrecto → 401 (`secrets.compare_digest`).
- **Tests** (3 nuevos · 32 total): barrido por TZ/hora/toggle, dedup por día,
  skip si guardó, endpoint protegido.

**Infra:** Cloud Scheduler `dwellia-aviso` (europe-west1, `*/15 * * * *`, header
con secreto, deadline 120s) → URL directa de Cloud Run. Secreto en
`.deploy/aviso_secret.txt` (gitignored) + env de Cloud Run (rev 00010).
⚠️ El flag correcto es `--headers` (no `--update-headers`, ese es de `update`).

**Estado: pipeline COMPLETO y verificado en prod, email APAGADO** (`enviados: 0`)
