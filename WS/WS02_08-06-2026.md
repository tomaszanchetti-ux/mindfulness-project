## Qué se hizo

**M0 — Biblioteca de cartas ✅ (v1 cerrada)**
- **69 cartas** escritas y curadas: 12 por categoría, salvo **Vínculos (9)** porque tiene 3 moldes. Los **23 moldes** cubiertos.
- Viven en `M0_Motor_de_Contenido/data/` en **3 seed JSON** (el SSOT que mañana es la DB):
  - `categorias.json` (6) + `acciones.json` (5) → fijos, salieron del molde.
  - `cartas.json` (69) → la biblioteca que crece. Cada carta guarda **solo** `categoria + accion + frase + prompt`; lo visual (color/png/glifo) se **joinea al renderizar** → crecer = sumar filas, nada más.
- Validado: sin referencias rotas, IDs únicos, 23 moldes exactos. Formato de id `{cat}-{accion}-{NN}`.

**Regla de estilo canonizada** (en `Madre_del_Motor.md`, §2)
- **Frase:** corta, poética, abstracta, memorable; *resuena* con la acción pero **no la explica**. Si guiña al motivo de la categoría (amanecer, luna…), mejor.
- **Acción:** genérica y libre, realizable cualquier día, **sin suponer nada** (encuentros, clima, cantidades). El foco está acá.
- **Tono:** español neutro.

**Stack y datos — N3 ✅ definido** (Documento Madre §5, espejo de Arc One)
- Front **React Native + Expo** (app móvil real; misma familia React que Arc One) · API **Cloud Run (Python)** · DB **Cloud SQL (PostgreSQL)** · login **Firebase Auth** · imágenes **Cloud Storage**.
- **Dos mundos de datos** (regla de aislamiento): contenido = tablas **globales** compartidas (acá vive M0) · datos de usuario = **privados**, cada fila con `user_id` y toda query filtra por usuario logueado. *No* una base por usuario.

**Principios**
- Principio 3 reescrito: **"Integralidad"** — la app es un todo interconectado; cada motor toma del anterior y resuelve para los siguientes; toda definición, completa e integral.
