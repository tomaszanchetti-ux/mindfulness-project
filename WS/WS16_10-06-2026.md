## 1 · Backend — storage dual + 3 endpoints (espejo del patrón auth dev/firebase)

- **`services/storage.py` (nuevo):** dónde viven los archivos. Dos modos por env:
  `MINDFUL_STORAGE_MODE=local` (disco bajo `MINDFUL_STORAGE_DIR`, default
  `var/fotos` — dev y tests) | `gcs` (bucket privado `MINDFUL_FOTOS_BUCKET`).
  El cliente de GCS **ya venía con firebase-admin** → cero libs nuevas para gcs.
  `storage_path` canónico igual en ambos modos:
  `fotos/{usuario_id}/{entrega_id}/{foto_id}.{ext}` — carpeta por usuario (canon M4:
  el aislamiento también en Storage).
- **`services/fotos.py` + `routers/fotos.py` (nuevos):**
  - `POST /api/entregas/{id}/fotos` (multipart, campo `foto`) — hasta **3 por
    entrega** (canon M3), solo imágenes (jpg/png/webp/gif/heic), **≤8 MB**, dueño
    o 404. Archivo primero, fila después (si la DB falla se limpia el archivo).
  - `GET /api/fotos/{id}` — **la imagen solo para su dueño** (Cache-Control
    private). Las fotos JAMÁS son públicas ni tienen URL de Storage expuesta.
  - `DELETE /api/fotos/{id}` — quitar (archivo + fila).
- **Baúl:** `fotos` ahora devuelve URLs de la API (`/api/fotos/{id}`), no
  storage_paths. El **borrado de entrega borra también los archivos** de Storage
  (antes solo caía la fila por cascade y el archivo quedaba huérfano).
- **Dependencia nueva:** `python-multipart==0.0.20` (FastAPI la necesita para
  UploadFile). `.gitignore` + `apps/api/var/`.
- **Tests: 22 passed** (5 nuevos en `tests/test_fotos.py`): subir+servir+listar ·
  límite 3 + formatos + vacía · aislamiento entre usuarios (y sin headers cae a
  `dev|user` → 404) · quitar borra archivo+fila · borrar entrega limpia Storage.

## 2 · Front — subida real + imágenes privadas

- **`api.ts`:** `hacerFetch` ya no fuerza Content-Type JSON con FormData ·
  `subirFoto(entregaId, file)` · `borrarFoto(id)` · **`fotoPrivadaUrl(url)`** =
  un `<img>` no puede mandar el Bearer, así que la imagen se baja con fetch
  autenticado y se muestra como object URL (cache por sesión de página).

  autoguardado de M3).

  `assetUrl(storage_path)` que nunca funcionó).
