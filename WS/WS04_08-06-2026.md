# WS04 — 08/06/2026 · Definición de M2 (Entrega del Día)

Cuarta sesión. Bajó la **lógica conceptual + la técnica de M2** (el "mixer" que elige
la carta de cada día). Fiel al método incremental, pero acá sí aparece el **primer
script ejecutable**: corre contra el seed de M0 y prueba la lógica en vivo. Vive en
`M2_Entrega_del_Dia/` (`Madre_del_Motor.md` = lógica · `entrega.py` = script · `README.md`).

## Qué se hizo

**M2 — Lógica ✅ (v1 cerrada) + script de referencia corriendo.** El motor trabaja en
**dos capas**:
1. **Categoría = filtro duro** (la elige el usuario en M1, 2-6). El pool del día son sólo esas.
2. **Acción = preferencia blanda** que la app **aprende de las estrellas** y usa para inclinar.

Flujo: ¿primera carta? → random · armo pool de mis categorías · saco las de los últimos
7 días · peso a cada candidata (+ afinidad de acción, − repetir acción/categoría de ayer,
piso para todas) · **sorteo ponderado** (la preferencia inclina, el azar decide) · entrego
+ vigencia 24h + aviso.

**Script `entrega.py`:** función pura `elegir_carta(perfil, cartas, modo)` + simulación de
21 días. Verificado: en v1 reparto parejo, en v2 concentra hacia las acciones puntuadas
alto pero ninguna desaparece; 0 repeticiones dentro de 7 días; primera carta random. Hoy
lee los JSON de M0; al construir el stack, la misma función se enchufa a Postgres.

## Decisiones canónicas (las 3 que decidió Tomás + refinamientos)

- **No-repetición = 7 días** (no 60, no ventana adaptativa). *"Con una semana de contenido
  distinto, ya alcanza."* — simplifica un montón (Simpleza).
- **Puntuación = 1-5 ⭐, opcional pero transparente.** El usuario sabe que ayuda a
  customizar la experiencia. Se **explica en el slideshow** (pantalla acción diaria) y se
  **practica en la carta de prueba** (M1); se usa en cada ritual (M3); la aprovecha M2.
  Alimenta sobre todo la **afinidad de acción**.
- **Primera carta = random** y el script lo deduce solo (historial vacío, sin rama especial).
- **Evolución v1 suave → v2 fuerte** (idea de Tomás), disparada por el **historial** (haber
  probado+puntuado las 5 modalidades), no por fecha. Refinamiento Claude aceptado: el
  **guardarraíl del comodín** — v2 concentra ~80% en las favoritas pero deja ~20% de
  sorpresa (1/semana una modalidad olvidada). Razón: anti eco-cámara + *la modalidad que
  evitás suele ser la más valiosa*. Lema: **"el motor te conoce, pero no te subestima."**
  v1 es lo que se lanza; v2 se activa con datos reales de uso.

- **Tabla nueva:** `entregas` (privada, `user_id`): carta_id, categoria, accion,
  fecha_entrega, vigente_hasta, estrellas (NULL si no puntuó), completada.
